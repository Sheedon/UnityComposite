# Sheedon.Hex 基础库总览

当前版本为 **`0.3.0`**。它是一个独立、纯 C#、不依赖 `UnityEngine` 的尖顶六边形基础库，已经完成：

- Core：坐标、拓扑与几何
- Map：有限区域、形状和数据层
- Algorithms：图契约与搜索算法

## 1. 核心定位

这个库负责回答：

- 六边形坐标是什么
- 两个六边形是否相邻
- 两点之间有多远
- 某张有限地图包含哪些格子
- 每个格子可以挂载什么数据
- 一条边是否允许通过
- 通过一条边需要多少 Cost
- 如何寻找路径、移动范围和连通区域

它只提供机制，不包含游戏业务。

明确不负责：

- Terrain、Elevation、Resource、Feature
- 单位、建筑、阵营、所有权
- 步行、飞行等具体移动规则
- GameObject、Mesh、Material、Shader
- 网格渲染、选中、拾取、边框表现
- Chunk、地图存档、流式加载
- 异步调度、Jobs、Burst、线程池

## 2. 固定几何约定

当前第一版只支持：

| 项目 | 约定 |
|---|---|
| 六边形朝向 | 尖顶 `pointy-top` |
| 逻辑坐标 | Axial `Q/R` |
| 第三轴 | `S = -Q - R` |
| 偏移矩形 | `odd-r` |
| Cost | 严格大于 0 的 `int` |
| 运行时命名空间 | `Sheedon.Hex` |

六方向数值已经固定：

```text
NE = 0
E  = 1
SE = 2
SW = 3
W  = 4
NW = 5
```

这些数值可以被序列化、网络协议或配置引用，因此不应随意修改。

## 3. Core 模块

### HexCoord

[HexCoord.cs](Runtime/Core/HexCoord.cs)

不可变轴向坐标：

```csharp
var coord = new HexCoord(2, -1);

coord.Q; // 2
coord.R; // -1
coord.S; // -1
```

支持：

- `Zero`
- Equality 与 Hash
- `+`、`-`、取反
- `==`、`!=`
- `ToString`
- 作为 `Dictionary` 和集合键使用

它只表达坐标，不包含地图成员资格、地形或可通行性。

### HexDirection

[HexDirection.cs](Runtime/Core/HexDirection.cs)

提供固定六方向，以及：

- `Opposite()`
- `Next()`
- `Previous()`

### HexTopology

[HexTopology.cs](Runtime/Core/HexTopology.cs)

负责无限六边形空间中的纯拓扑：

- `GetNeighbor`
- `GetNeighbors`
- `Distance`
- `GetRange`
- `GetRing`
- `GetSpiral`

这里不会检查坐标是否属于某张地图。即使目标坐标不存在于有限区域，`GetNeighbor` 仍然会返回理论邻居。

### HexGeometry

[HexGeometry.cs](Runtime/Core/HexGeometry.cs)

负责连续坐标与离散格子的几何运算：

- `Round(q, r)`
- `GetLine(from, to)`

`GetLine` 返回包含起点和终点的连续六边形路径，但不判断中间是否存在障碍。

### HexPoint

[HexPoint.cs](Runtime/Core/HexPoint.cs)

库内自己的二维浮点坐标，仅包含：

```text
X
Y
```

它用于隔离 `UnityEngine.Vector2/Vector3`。

### HexLayout

[HexLayout.cs](Runtime/Core/HexLayout.cs)

负责尖顶六边形的逻辑坐标和二维坐标转换：

- `HexToPoint`
- `PointToHex`
- `GetCorner`

尖顶布局公式为：

```text
X = Size × √3 × (Q + R / 2)
Y = Size × 3/2 × R
```

角点从 `30°` 开始，每次增加 `60°`，因此生成的几何结构为尖顶六边形。

## 4. Map 模块

### HexRegion

[HexRegion.cs](Runtime/Map/HexRegion.cs)

表示一张有限地图实际包含哪些坐标。

支持：

- `Count`
- `Contains`
- `Add`
- `Remove`
- 枚举全部坐标
- 构造时自动去重

它允许动态修改，可用于地图生成、编辑器和区域扩张。

必须注意：

```text
不存在于 Region
```

和：

```text
存在，但当前规则不能通过
```

是两个完全独立的概念。

### HexShapes

[HexShapes.cs](Runtime/Map/Shapes/HexShapes.cs)

所有形状最终都生成普通 `HexRegion`，不会产生不同的地图子类。

支持：

| 方法 | 语义 |
|---|---|
| `CreateHexagon` | 按 Hex Distance 生成大六边形 |
| `CreateRectangle` | 按尖顶 `odd-r` 行列生成矩形 |
| `CreateSquare` | 等宽等高矩形 |
| `CreateCircle` | 按格子中心的真实二维距离生成圆形 |
| `CreateParallelogram` | 按闭区间 Q/R 边界生成轴向平行四边形 |
| `CreateFromCoordinates` | 从任意坐标集合生成不规则区域 |

矩形和正方形的 `origin` 表示偏移坐标意义下的左上角。

`CreateCircle` 与 `CreateHexagon` 不同：

- Hexagon 使用拓扑距离
- Circle 使用 `HexLayout` 计算后的几何距离

### HexLayer\<T>

[HexLayer.cs](Runtime/Map/HexLayer.cs)

给一个 `HexRegion` 中的坐标挂载一种数据。

例如：

```csharp
var terrain = new HexLayer<TerrainId>(region);
var elevation = new HexLayer<int>(region);
var units = new HexLayer<UnitId>(region);
```

支持：

- `Get`
- `Set`
- `TryGet`
- `Contains`
- 枚举已赋值数据

访问规则：

- 区域外 `Get/Set`：抛出 `ArgumentOutOfRangeException`
- 区域内但未赋值的 `Get`：抛出 `KeyNotFoundException`
- `TryGet`：失败返回 `false`
- 枚举时只返回当前区域内的有效数据

如果某个坐标被移除后重新加入，旧 Layer 数据不会自动复活，避免新一代格子意外继承旧数据。

## 5. Algorithms 模块

Algorithms 不直接依赖具体地图业务，而是通过两个契约运行。

### IHexGraph

[IHexGraph.cs](Runtime/Algorithms/Graph/IHexGraph.cs)

负责回答：

```text
这个节点是否存在？
这个节点有哪些直接邻居？
```

接口包括：

```csharp
bool Contains(HexCoord coord);

IEnumerable<HexCoord> GetNeighbors(HexCoord coord);
```

返回的邻居必须：

- 属于图
- 与当前坐标的 Hex Distance 为 1
- 不得返回 `null`

### RegionHexGraph

[RegionHexGraph.cs](Runtime/Algorithms/Graph/RegionHexGraph.cs)

将 `HexRegion` 适配为 `IHexGraph`：

```text
HexTopology.GetNeighbors
        ↓
过滤不属于 Region 的坐标
        ↓
得到有限地图邻居
```

它与 Region 实时绑定，Region 增删坐标后不需要重新创建 Graph。

### IHexTraversalRule

[IHexTraversalRule.cs](Runtime/Algorithms/Graph/IHexTraversalRule.cs)

负责回答：

```csharp
bool CanTraverse(HexCoord from, HexCoord to);

int GetCost(HexCoord from, HexCoord to);
```

这是游戏规则进入基础库的边界。

例如：

- WalkingRule 可以禁止海洋并提高山地 Cost
- FlyingRule 可以允许飞越海洋并统一 Cost
- 同一张图可以同时配合多种移动规则

边是有方向的，因此允许：

```text
A → B 可以通过
B → A 不可以通过
```

所有可通行边的 Cost 必须大于 0，否则加权算法会抛出异常。

## 6. 路径算法

### BreadthFirstSearch

[BreadthFirstSearch.cs](Runtime/Algorithms/Pathfinding/BreadthFirstSearch.cs)

适用于无权图：

- 遵守 `CanTraverse`
- 不读取 `GetCost`
- 返回经过边数最少的路径
- `TotalCost` 表示步数

### Dijkstra

[Dijkstra.cs](Runtime/Algorithms/Pathfinding/Dijkstra.cs)

适用于不同边 Cost：

- 返回实际 Cost 最低的路径
- 路径可能步数更多，但总代价更低
- 检查非正 Cost
- 累积 Cost 超出 `int` 时抛出 `OverflowException`

### AStar

[AStar.cs](Runtime/Algorithms/Pathfinding/AStar.cs)

在 Dijkstra 基础上加入启发函数：

- 默认启发函数为 `HexTopology.Distance`
- 可以传入自定义 `Func<HexCoord, HexCoord, int>`
- 启发值不得为负
- 自定义启发函数不高估真实剩余 Cost 时，才能保证最优路径

由于边 Cost 至少为 1、邻居 Hex Distance 为 1，因此默认 Hex Distance 是可采纳的。

## 7. 路径结果

[HexPathResult.cs](Runtime/Algorithms/Results/HexPathResult.cs)

包含：

```text
Status
Path
TotalCost
```

状态为：

| 状态 | 含义 |
|---|---|
| `Success` | 找到路径 |
| `NoPath` | 起终点有效，但无法到达 |
| `InvalidStart` | 起点不在图中 |
| `InvalidGoal` | 目标不在图中 |

成功路径包含起点和目标。

失败结果：

```text
Path = 空
TotalCost = 0
```

当 `start == goal` 时：

```text
Status = Success
Path = [start]
TotalCost = 0
```

## 8. CostRange

[CostRange.cs](Runtime/Algorithms/Range/CostRange.cs)

输入：

```text
Start
MaximumCost
```

输出 `HexRangeResult`：

- 预算内所有可达坐标
- 到达每个坐标的最低 Cost
- `Contains`
- `GetMinimumCost`
- `TryGetMinimumCost`
- `Coordinates`
- `Count`

起点本身 Cost 为 0。

如果起点不在图中：

```text
IsStartValid = false
Count = 0
```

这可以直接用于战斗移动范围或行动力范围计算。

## 9. FloodFill

[FloodFill.cs](Runtime/Algorithms/FloodFill/FloodFill.cs)

返回从起点出发、遵守 `CanTraverse` 后能够访问的完整连通区域。

特点：

- 使用稳定的广度优先顺序
- 不读取边 Cost
- 支持有方向的通行规则
- 无效起点返回空集合

适用于区域划分、地图生成、连通性检查等场景。

## 10. 推荐接入流程

```text
创建 HexLayout
      ↓
生成 HexRegion
      ↓
创建 HexLayer<T>
      ↓
使用 RegionHexGraph 适配区域
      ↓
由游戏层实现 IHexTraversalRule
      ↓
调用 BFS / Dijkstra / A* / CostRange / FloodFill
```

典型代码：

```csharp
var layout = new HexLayout(1d);

var region = HexShapes.CreateHexagon(HexCoord.Zero, 5);
var terrain = new HexLayer<TerrainId>(region);

var graph = new RegionHexGraph(region);
var movementRule = new WalkingTraversalRule(terrain);

var result = AStar.FindPath(
    graph,
    movementRule,
    HexCoord.Zero,
    new HexCoord(3, -2));

if (result.Status == HexPathStatus.Success)
{
    foreach (var coord in result.Path)
    {
        // 交给上层移动或表现系统
    }
}
```

`TerrainId` 和 `WalkingTraversalRule` 属于消费方，不属于这个基础库。

## 11. 工程边界

工程采用两个程序集：

| 程序集 | 用途 |
|---|---|
| `Sheedon.Hex` | 全部 Runtime 代码 |
| `Sheedon.Hex.Tests` | Editor 下的 NUnit 测试 |

逻辑依赖关系：

```text
             Core
            /    \
           ↓      ↓
         Map   Algorithms
```

Algorithms 只通过图与通行契约执行搜索；`RegionHexGraph` 是连接 Map 和 Algorithms 的窄适配器。

运行时程序集设置了 `noEngineReferences`，因此可以：

- 在 Unity 中使用
- 在普通纯 C# 测试环境中运行
- 被游戏逻辑、服务器逻辑或工具代码复用
