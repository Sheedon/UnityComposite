## 库的功能

`Sheedon.Hex` 是一个不依赖 `UnityEngine` 的纯 C# 尖顶六边形基础库，提供三层能力：

- **Core**：轴向坐标、六方向、邻居、距离、范围、环、螺旋、直线，以及逻辑坐标与二维平面坐标互转。
- **Map**：有限区域 `HexRegion`、常用区域形状 `HexShapes`、按区域挂载数据的 `HexLayer<T>`。
- **Algorithms**：图与通行规则契约，以及 BFS、Dijkstra、A*、CostRange、FloodFill。

它只提供六边形机制。地形、高程、资源、单位、建筑、阵营、移动类型、渲染、Mesh、GameObject、拾取、存档、Chunk 和异步调度属于消费方。

## 核心思想

```text
HexCoord / HexTopology / HexLayout       Core：无限六边形空间
                 ↓
       HexRegion + HexLayer<T>           Map：有限成员资格与业务数据
                 ↓
 RegionHexGraph + IHexTraversalRule      边界：图结构与游戏规则
                 ↓
 BFS / Dijkstra / A* / Range / Fill      Algorithms：无业务含义的搜索
```

最重要的分离原则：

- **坐标不等于地图格子**：`HexCoord` 可以表示无限空间中的任意位置；`HexRegion.Contains` 才回答格子是否属于有限地图。
- **存在不等于可通行**：`IHexGraph` 管节点和邻接，`IHexTraversalRule` 管某条有向边能否通过及其 Cost。
- **机制不等于业务**：地形和单位数据放在消费方定义的 `HexLayer<T>` 中，移动规则也由消费方实现。
- **逻辑不等于表现**：库使用 `HexPoint(double X, double Y)`，与 Unity 的 `Vector2`/`Vector3` 转换放在集成层。
- **形状是数据，不是类型层级**：所有 `HexShapes` 方法都返回普通 `HexRegion`，不会为矩形、圆形等建立地图子类。

## 固定约定

| 项目 | 约定 |
|---|---|
| 朝向 | 尖顶（pointy-top） |
| 逻辑坐标 | Axial `Q/R`，`S = -Q - R` |
| 矩形偏移坐标 | `odd-r` |
| 方向顺序 | `NE=0, E=1, SE=2, SW=3, W=4, NW=5` |
| 边 | 有方向，允许 `A→B` 与 `B→A` 的规则不同 |
| 加权边 Cost | 严格大于 `0` 的 `int` |
| Runtime | 单程序集 `Sheedon.Hex`，`noEngineReferences: true` |

方向数值可能进入序列化、协议或配置，不要随意改序号。当前仅支持尖顶布局；不要在未扩展设计与测试的情况下混入平顶公式。

## 核心用法

### 1. 坐标、拓扑和几何

```csharp
using Sheedon.Hex;

var origin = HexCoord.Zero;
var east = HexTopology.GetNeighbor(origin, HexDirection.E);
var distance = HexTopology.Distance(origin, new HexCoord(3, -2));

var range = HexTopology.GetRange(origin, 3);
var ring = HexTopology.GetRing(origin, 3);
var line = HexGeometry.GetLine(origin, new HexCoord(3, -2));

var layout = new HexLayout(1d, HexPoint.Zero);
HexPoint center = layout.HexToPoint(east);
HexCoord picked = layout.PointToHex(center);
layout.GetEdgeCorners(east, HexDirection.NE, out var edgeStart, out var edgeEnd);
```

`GetNeighbor`、`GetRange` 和 `GetLine` 都在无限拓扑上工作，不会检查地图边界或障碍。

### 2. 有限地图和数据层

```csharp
var region = HexShapes.CreateHexagon(HexCoord.Zero, 5);
var terrain = new HexLayer<TerrainId>(region);
var elevation = new HexLayer<int>(region);

terrain.Set(HexCoord.Zero, TerrainId.Plain);
elevation.Set(HexCoord.Zero, 2);
```

可用形状：`CreateHexagon`、`CreateRectangle`、`CreateSquare`、`CreateCircle`、`CreateParallelogram`、`CreateFromCoordinates`。

`HexLayer<T>` 绑定一个 `HexRegion`：

- 区域外 `Get`/`Set` 会抛出 `ArgumentOutOfRangeException`。
- 区域内但未赋值时，`Get` 会抛出 `KeyNotFoundException`；不确定时优先用 `TryGet`。
- 从 Region 移除坐标再重新加入后，旧值不会复活；需要由消费方重新赋值。
- 枚举 Layer 时只返回当前仍有效且已赋值的条目。

### 3. 图、通行规则与搜索

普通有限区域直接用 `RegionHexGraph`：

```csharp
var graph = new RegionHexGraph(region);
```

消费方为每种移动模式实现 `IHexTraversalRule`。示例：

```csharp
public sealed class WalkingRule : IHexTraversalRule
{
    private readonly HexLayer<int> _moveCost;

    public WalkingRule(HexLayer<int> moveCost) => _moveCost = moveCost;

    public bool CanTraverse(HexCoord from, HexCoord to) =>
        _moveCost.TryGet(to, out var cost) && cost > 0;

    public int GetCost(HexCoord from, HexCoord to)
    {
        if (TryGetCost(from, to, out var cost)) return cost;
        throw new InvalidOperationException("The directed edge is not traversable.");
    }

    public bool TryGetCost(HexCoord from, HexCoord to, out int cost)
    {
        if (_moveCost.TryGet(to, out cost) && cost > 0) return true;
        cost = 0;
        return false;
    }
}
```

然后按问题选择算法：

| 需求 | API | 读取规则 | 结果含义 |
|---|---|---|---|
| 最少步数路径 | `BreadthFirstSearch.FindPath` | `CanTraverse` | `TotalCost` 是步数 |
| 最低 Cost 路径 | `Dijkstra.FindPath` | `TryGetCost` | 保证正权边下的最低总代价 |
| 更快的最低 Cost 搜索 | `AStar.FindPath` | `TryGetCost` | 默认启发式为 Hex Distance |
| 预算内移动范围 | `CostRange.Find` | `TryGetCost` | 保存每格的最低到达 Cost |
| 完整连通区域 | `FloodFill.FindConnected` | `CanTraverse` | 返回稳定的广度优先顺序 |

```csharp
var moveCost = new HexLayer<int>(region);
foreach (var coord in region)
{
    moveCost.Set(coord, 1);
}

var rule = new WalkingRule(moveCost);
var result = AStar.FindPath(graph, rule, start, goal);

if (result.Status == HexPathStatus.Success)
{
    foreach (var coord in result.Path)
    {
        // 交给消费方的移动或表现系统。
    }
}
```

`HexPathResult.Path` 的成功结果包含起点和终点。失败状态有 `NoPath`、`InvalidStart`、`InvalidGoal`，失败时路径为空且 `TotalCost` 为 `0`。`start == goal` 时返回单节点成功路径。

自定义 A* 启发值必须非负；只有不高估真实剩余 Cost 时才保证最优。加权算法遇到可通行但非正的 Cost 会抛出异常，累计 Cost 溢出也会失败，不要用 `0` 表示免费边。

## 何时自定义 IHexGraph

`RegionHexGraph` 适合绝大多数有限地图。只有当节点并非简单来自一个 `HexRegion`，或邻接需要传送门等自定义连接时，才实现 `IHexGraph`。实现必须保证：

- `Contains` 准确反映有效节点。
- `GetNeighbors` 不返回 `null`。
- 普通邻居必须属于图且与当前节点的 Hex Distance 为 `1`。

如果业务需要非相邻连接，应先核对现有契约和算法校验逻辑，不要悄悄突破接口语义。

## 修改时必须保持的边界

- `Runtime` 保持纯 C#，不添加 `UnityEngine` 引用。
